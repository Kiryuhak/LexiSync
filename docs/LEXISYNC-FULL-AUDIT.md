## 2. Карта проекта и поток данных

Основной поток: popup/контекстное меню/hotkey/панель выделения → `src/content.ts` и snapshot выделения → сообщения `src/background.ts` → выбор режима (`speller`, `ai`, `hybrid`) → Яндекс.Спеллер и/или Mistral/Cloudflare → `src/ai-sanity-check.ts` → UI результата → `src/text-replacement.ts`.

Настройки проходят через `settings-store`, `settings-migrations`, runtime-cache и import/export. Секреты вынесены в `secret-store`. Резервная копия шифруется AES-GCM 256 с PBKDF2 и хранится в `appDataFolder` Google Drive. Логи ошибок локальны. Сборка WXT формирует отдельные MV3 Chrome/Firefox manifests; tag workflow собирает, проверяет и публикует ZIP.

Положительные результаты:

- Три режима маршрутизации реализованы; hybrid валидирует фактический AI input после Speller, fallback ограничен двумя провайдерами и не зацикливается.
- Cooldown хранится в `storage.session`, выдерживает перезапуск MV3 service worker; это подтверждено E2E.
- Mistral основной текстовый запрос не имеет внутреннего бесконтрольного retry; Cloudflare spellcheck non-streaming, style streaming; abort/timeout/пустые и malformed ответы обработаны.
- Snapshot для input/textarea и contenteditable проверяет исходное значение, диапазон, root и подключённость узлов до замены. Stale response и изменённый DOM блокируются.
- HTML результата строится через безопасные DOM primitives; пользовательский Markdown не передаётся в `innerHTML`; секреты не выдаются content script.
- Live proofread использует нативный `spellcheck` и не отправляет ввод в сеть; проверено E2E.
- Реальный Яндекс.Спеллер подтвердил POST, `ru,en`, UTF-8, UTF-16 позицию после emoji и `[]` для корректного текста. Клиент ограничивает длину, имеет timeout/abort и не делает retry-loop.

## 4. Подробные находки

### AUD-001 — миграция локального корректора без согласия включает сетевой Speller

- **Категория / статус / приоритет:** приватность, migration; подтверждённый баг; влияние высокое, вероятность подтверждена.
- **Путь / участок:** `src/settings-migrations.ts` (`migrateLegacySettings`), `src/runtime-settings-cache.ts` (`normalizeProofreadMode`), `src/settings-transfer.ts` (`sanitizePortableSetting`).
- **Воспроизведение:** сохранить или импортировать legacy `proofreadMode: "local"`, затем выполнить проверку орфографии.
- **Фактически:** все три пути преобразуют `local` в `speller`; выбранный текст может уйти Яндексу, хотя пользователь ранее выбирал локальную обработку.
- **Ожидаемо:** явное согласие на сетевую передачу либо безопасный локальный/отключённый режим до выбора пользователя.
- **Причина / последствия:** семантически несовместимые режимы объединены механической миграцией; нарушается прежнее privacy-намерение.
- **Исправление / тест:** миграция в состояние `needsProofreaderChoice`, блок сетевого вызова до подтверждения; unit + upgrade E2E с утверждением `fetch` не вызван.
- **Зависимости / трудоёмкость:** тексты onboarding/privacy и схема настроек; средняя.

### AUD-002 — sanity check пропускает изменение чисел с единицами и валюты

- **Категория / статус / приоритет:** AI quality/data integrity; подтверждённый баг; влияние высокое, вероятность подтверждена.
- **Путь / участок:** `src/ai-sanity-check.ts`, извлечение числовых токенов и `validateNumericIntegrity`/`validateAiOutput`.
- **Воспроизведение:** временная диагностика показала `valid: true` для `2026г.→2027г.`, `12кг→13кг`, `100 ₽→100 $` в spellcheck.
- **Фактически:** boundary `(?![\p{L}\p{N}_])` исключает число перед буквой; символ валюты не связан с числовым токеном.
- **Ожидаемо:** любое изменение значения, единицы, процента или валюты в spellcheck отклоняется.
- **Причина / последствия:** числовая модель токена неполна; AI может незаметно исказить дату, массу или стоимость.
- **Исправление / тест:** токенизировать signed number + separators + attached unit/currency как защищённую сущность; parameterized tests для дефиса/en/em dash, NBSP/NNBSP, дат, версий, IP, URL, процентов и повторов.
- **Зависимости / трудоёмкость:** определить допустимые нормализации форматирования; средняя.

### AUD-003 — Undo перезаписывает изменения, сделанные пользователем после замены

- **Категория / статус / приоритет:** DOM replacement/data loss; подтверждённый баг; влияние высокое, вероятность подтверждена.
- **Путь / участок:** `src/text-replacement.ts`, closures `undoFn` для input/textarea в replace и append; вызов из `src/content-result-actions.ts`.
- **Воспроизведение:** заменить выделение, вручную дописать текст в поле, нажать Undo LexiSync.
- **Фактически:** closure без проверки восстанавливает весь `oldValue`, уничтожая последующие правки.
- **Ожидаемо:** undo доступен только при совпадении текущего post-replacement snapshot либо отменяет исключительно диапазон LexiSync.
- **Причина / последствия:** сохраняется полное старое значение, но не postcondition/version; подтверждённая потеря пользовательского текста.
- **Исправление / тест:** compare-and-swap по `nextValue` и точечный inverse edit; E2E input/textarea с редактированием до Undo.
- **Зависимости / трудоёмкость:** согласовать UX для устаревшего undo; средняя.

### AUD-004 — импорт строкового `"false"` включает privacy-sensitive настройки

- **Категория / статус / приоритет:** settings/privacy; подтверждённый баг; влияние высокое, вероятность подтверждена.
- **Путь / участок:** `src/settings-transfer.ts`, `sanitizePortableSetting`.
- **Воспроизведение:** импортировать `sendPageContext: "false"` (аналогично другие boolean keys).
- **Фактически:** выражение `value !== false` возвращает `true`; диагностика это подтвердила.
- **Ожидаемо:** принимать только boolean или строго нормализованные `"true"/"false"`; невалидное значение отклонять.
- **Причина / последствия:** truthiness заменяет проверку типа; может включиться отправка контекста страницы, история или fallback без намерения пользователя.
- **Исправление / тест:** schema validation до каких-либо записей, fail-closed для privacy flags; parameterized import tests с `false`, `"false"`, `0`, `null`, object.
- **Зависимости / трудоёмкость:** формат portability и сообщения об ошибках; малая–средняя.

### AUD-012 — contenteditable Undo может отменить чужое последующее действие

- **Категория / статус / приоритет:** DOM replacement/data loss; потенциальный риск; влияние высокое, вероятность средняя.

- **Зависимости / трудоёмкость:** AUD-003 и selection-state; высокая.

- **Категория / статус / приоритет:** пробел тестирования/integration; влияние высокое, вероятность подтверждена.
- **Путь / участок:** `tests/e2e.spec.ts`, provider unit suites.
- **Воспроизведение:** все Mistral/Cloudflare E2E ответы перехватываются; реальный paid API намеренно не вызывался.
- **Фактически:** schema/model/SSE drift и реальные headers не проверяются. Приложенный лог показывает повторяющиеся Cloudflare `QUALITY_CHECK_FAILED` после Mistral 429, но не доказывает дефект маршрутизатора.
- **Ожидаемо:** opt-in contract canary на безопасном синтетическом тексте, не обязательный для fork PR.
- **Причина / последствия:** разумная экономия/секретность оставляет integration blind spot.
- **Исправление / тест:** scheduled/manual canary с жёстким cost cap, redacted artifacts и без пользовательских данных.
- **Зависимости / трудоёмкость:** CI secrets и бюджет; средняя.

### AUD-015 — fixed waits и CI retry могут маскировать flaky E2E

- **Категория / статус / приоритет:** технический долг тестов; влияние среднее, вероятность подтверждена.
- **Путь / участок:** `tests/e2e.spec.ts`, `tests/firefox.spec.ts`, `playwright.config.ts`.
- **Воспроизведение:** поиск `waitForTimeout`/`setTimeout`; CI разрешает retry.
- **Фактически:** значительная часть ожиданий основана на времени; упавший первый прогон может стать зелёным после retry.
- **Ожидаемо:** event/state-driven waits, отчёт о flaky отдельно от pass.
- **Причина / последствия:** тайминги вместо наблюдаемого состояния; медленный прогон (226,63 с) и риск скрытых races.
- **Исправление / тест:** заменить waits на assertions/events, публиковать retry count, отдельный no-retry nightly.
- **Зависимости / трудоёмкость:** AUD-013; средняя.

### AUD-016 — в Firefox toolchain остаются high advisories

- **Категория / статус / приоритет:** tooling security; подтверждённый риск; влияние среднее, вероятность подтверждена.
- **Путь / участок:** `package-lock.json`, overrides в `package.json`, `scripts/audit-tooling.mjs`.
- **Воспроизведение:** `npm audit --audit-level=high` → exit 1: 4 high + 1 moderate в `adm-zip` и `image-size` через `web-ext`/`addons-linter`.
- **Фактически:** production audit чист; проект принимает advisories как tooling-only. Уязвимости обрабатывают архивы/изображения в доверенном pipeline, поэтому это не runtime exploit расширения.
- **Ожидаемо:** обновлённые безопасные версии либо явно изолированная и ограниченная модель угроз.
- **Причина / последствия:** upstream dependency/override; компрометация или вредоносный вход CI может вызвать overwrite/DoS.
- **Исправление / тест:** проверить совместимое обновление, убрать override после исправления; полный npm audit + release build.
- **Зависимости / трудоёмкость:** upstream web-ext/addons-linter; средняя, частично внешняя.

### AUD-017 — release assets разрешено перезаписывать для существующего тега

- **Категория / статус / приоритет:** release integrity; потенциальный риск; влияние среднее, вероятность низкая.
- **Путь / участок:** `.github/workflows/release.yml`, `gh release upload ... --clobber`.
- **Воспроизведение:** повторно запустить workflow существующего тега с изменённой средой/зависимостями.
- **Фактически:** assets заменяются. Локальная двойная сборка сейчас дала одинаковые SHA-256 для Chrome, Firefox и sources ZIP, поэтому текущая недетерминированность не подтверждена.
- **Ожидаемо:** один тег неизменно связан с одними опубликованными hashes; конфликт требует ручного решения.
- **Причина / последствия:** удобство rerun важнее immutability; возможна историческая подмена артефакта той же версии.
- **Исправление / тест:** отказывать при другом hash, разрешать повтор только при полном совпадении; сохранять checksums/provenance.
- **Зависимости / трудоёмкость:** release policy; малая–средняя.

### AUD-018 — content panel не входит в полную responsive/a11y матрицу

- **Категория / статус / приоритет:** UI/accessibility, пробел тестирования; влияние среднее, вероятность подтверждена.
- **Путь / участок:** `tests/e2e.spec.ts`, тест accessibility extension pages и отдельные narrow-panel assertions.
- **Воспроизведение:** сопоставить axe-тест со страницами: injected result UI не проходит тот же полный аудит во всех темах/ширинах.
- **Фактически:** есть полезные проверки 320px, aria-label guard и extension pages axe, но нет системной матрицы 375/768/desktop, light/dark, zoom/keyboard для панели.
- **Ожидаемо:** единая матрица для popup/options/history и injected dialog.
- **Причина / последствия:** тесты фрагментированы; возможны визуальные/a11y регрессии без падения CI.
- **Исправление / тест:** parametrized screenshots + axe + keyboard/focus/zoom на 375/768/desktop и обеих темах.
- **Зависимости / трудоёмкость:** стабилизация waits AUD-015; средняя.

### AUD-019 — крупные монолитные UI-модули и bundle усложняют изменение

- **Категория / статус / приоритет:** performance/maintainability debt; влияние среднее, вероятность подтверждена.
- **Путь / участок:** `src/content-request-panel.ts` (~82,7 KB source), `src/options.ts` (~87,1 KB), `src/options-page.css` (~113,6 KB); release `inject.js` ~190,8 KB, options JS ~176,2 KB.
- **Воспроизведение:** production build size report.
- **Фактически:** сборка быстрая и общий ZIP мал; явная runtime-деградация не воспроизведена. Но большие связанные модули повышают parse/maintenance/test cost.
- **Ожидаемо:** измеряемые budgets и разделение по жизненному циклу без изменения UX.
- **Причина / последствия:** накопление UI/таймеров/действий в центральных файлах; регрессии труднее локализовать.
- **Исправление / тест:** сначала performance marks/budgets, затем безопасное выделение controllers; не переписывать архитектуру без профиля.
- **Зависимости / трудоёмкость:** после correctness и test stages; высокая.

### AUD-020 — mutation message handler не проверяет доверенный sender

- **Категория / статус / приоритет:** security defense-in-depth; потенциальный риск; влияние среднее, вероятность низкая.
- **Путь / участок:** `src/settings-store.ts`, обработчик storage mutation; сравнить с sender checks для secret actions в `src/background.ts`.
- **Воспроизведение:** привилегированный/скомпрометированный extension context отправляет `factoryReset`.
- **Фактически:** домен сообщения и payload проверяются, origin/sender для mutations — нет. Обычный page JS из-за isolated world напрямую этого сделать не может.
- **Ожидаемо:** destructive operations принимаются только от явно разрешённых extension pages/contexts.
- **Причина / последствия:** неравномерная authorization policy; повышается ущерб при компрометации другого контекста расширения.
- **Исправление / тест:** централизовать sender authorization, allowlist destructive actions; negative messaging tests.
- **Зависимости / трудоёмкость:** определить доверенные contexts; средняя.

## 6. Непроверенное и внешние ограничения

- Реальные Mistral/Cloudflare запросы не выполнялись из-за запрета ненужных платных API; значит, реальные schema/429/quota изменения остаются внешним ограничением.
- Firefox прошёл сборку, lint и temporary install, но не функциональную матрицу (AUD-013); совместимость нельзя считать полностью проверенной.
- Chrome store/AMO upload, OAuth с реальным аккаунтом Google Drive и service-worker termination во всех браузерах не выполнялись, чтобы не менять внешнее состояние.
- Потенциальные AUD-006—012, AUD-017 и AUD-020 не представлены как воспроизведённые production incidents.

## 7. Вывод

Базовая архитектура маршрутизации, snapshot-защита до вставки, обработка ошибок провайдеров и release validation заметно сильнее среднего. Главный остаточный риск сосредоточен не в бесконечных retry, а в трёх местах: сохранность текста при Undo, неполная защита фактических значений AI-ответа и изменение privacy-смысла настроек при migration/import. Исправления должны начинаться с воспроизводящих тестов и выполняться по отдельному разрешению.
