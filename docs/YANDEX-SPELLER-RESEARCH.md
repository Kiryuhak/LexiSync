## 1. Введение и цели исследования

Цель настоящего исследования — провести всесторонний анализ сервиса проверки правописания **Яндекс.Спеллер** (Yandex.Speller API) и эмпирически сопоставить его возможности с двумя текущими контурами проверки текста в **LexiSync**:

1. **Local Proofreader** — полностью автономный локальный движок расширения (фильтр Блума на 1,4 млн русских словоформ + детерминированные правила опечаток и базовой пунктуации, работающий с задержкой 0 мс без обращения к сети).
2. **AI-конвейер LexiSync** — облачные большие языковые модели (Cloudflare Workers AI `@cf/zai-org/glm-4.7-flash` и Mistral AI `mistral-small-latest` / `codestral-2501`).

### Ключевые вопросы исследования:

- Способен ли Яндекс.Спеллер заменить автономный Local Proofreader?
- Способен ли Яндекс.Спеллер заменить или разгрузить LLM в задаче исправления текста?
- Целесообразен ли трёхслойный каскад (Local $\to$ Speller $\to$ AI)?
- Каковы практические риски приватности, сетевые задержки и юридические обязательства (условия использования, брендинг, лимиты)?

## 2. Архитектура и спецификация API Яндекс.Спеллера

Сервис Яндекс.Спеллер предназначен для проверки орфографии русскоязычных, украиноязычных и англоязычных текстов. В основе сервиса лежат словарные базы системы **ОРФО** (разработка компании «Информатик», 2009) в сочетании со статистическими n-граммными моделями Яндекса.

### 2.1 Эндпоинты

| Метод          | URL                                                                | Описание                                       |
| :------------- | :----------------------------------------------------------------- | :--------------------------------------------- |
| `POST` / `GET` | `https://speller.yandex.net/services/spellservice.json/checkText`  | Проверка одного фрагмента текста               |
| `POST` / `GET` | `https://speller.yandex.net/services/spellservice.json/checkTexts` | Пакетная проверка нескольких фрагментов текста |

Сервис также поддерживает устаревшие форматы XML и SOAP, однако для современных веб-расширений актуален исключительно интерфейс JSON.

### 2.2 Входные параметры `checkText`

- `text` (строка, обязательный): проверяемый текст. Документация указывает ограничение до 10 000 символов (в POST-запросе).
- `lang` (строка, по умолчанию `ru,en`): список проверяемых языков через запятую (`ru`, `en`, `uk`).
- `options` (целое число, по умолчанию `0`): битовая маска пользовательских настроек.
- `format` (строка, по умолчанию `plain`): формат текста (`plain` — обычный текст, `html` — HTML-разметка, при которой теги игнорируются).

### 2.3 Битовая маска `options`

| Флаг     | Бит (dec) | Константа в документации | Описание                                                          |
| :------- | :-------: | :----------------------- | :---------------------------------------------------------------- |
| `0x0001` |     1     | `IGNORE_UPPERCASE`       | Пропускать слова, написанные ЗАГЛАВНЫМИ буквами (аббревиатуры).   |
| `0x0002` |     2     | `IGNORE_DIGITS`          | Пропускать слова с цифрами (например, `а10б`, `pass123`).         |
| `0x0004` |     4     | `IGNORE_URLS`            | Пропускать адреса сайтов, email-адреса и имена файлов.            |
| `0x0008` |     8     | `FIND_REPEAT_WORDS`      | Подсвечивать повторы слов, идущих подряд («сегодня сегодня»).     |
| `0x0200` |    512    | `IGNORE_CAPITALIZATION`  | Игнорировать ошибки написания строчных/прописных букв («москва»). |

### 2.4 Формат ответа и коды ошибок

Пример ответа:

```json
[
    {
        "code": 1,
        "pos": 0,
        "row": 0,
        "col": 0,
        "len": 6,
        "word": "Карова",
        "s": ["Корова", "Карпова"]
    }
]
```

Значения полей:

- `code` — код ошибки:
    - `1`: `ERROR_UNKNOWN_WORD` — слово не найдено в словаре;
    - `2`: `ERROR_REPEAT_WORD` — повтор слова (требует опции 8);
    - `3`: `ERROR_CAPITALIZATION` — неверное употребление регистра;
    - `4`: `ERROR_TOO_MANY_ERRORS` — текст содержит слишком много ошибок, проверка прервана.
- `pos` — начальная позиция ошибочного слова в символах (0-indexed UTF-16 offset).
- `row`, `col` — строка и колонка ошибки.
- `len` — длина ошибочного фрагмента.
- `word` — исходное слово.
- `s` — массив подсказок (вариантов исправления), упорядоченный по релевантности.

## 4. Методика тестирования

Для получения достоверных фактических данных был разработан автоматизированный тестовый комплекс из **45 сценариев**, охватывающих 10 лингвистических и технических категорий:

1. **Орфография (простые опечатки):** слова с перепутанными, пропущенными или удвоенными буквами.
2. **Контекстные опечатки и паронимы:** слова, существующие в словаре, но неуместные по смыслу («скучать музыку», «компания началась», «одел пальто»).
3. **Повторение слов:** идущие подряд дубликаты («сегодня сегодня»).
4. **Регистр букв:** «мОСКВЕ», строчное написание городов.
5. **Грамматическое согласование:** согласование рода, числа, падежей в предложении.
6. **Пунктуация:** сложные предложения, вводные слова, обращения, однородные члены, знаки вопроса.
7. **Заведомо правильный текст (Zero False-Positive test):** чистые предложения для проверки ложных срабатываний.
8. **Правила орфографии повышенной сложности:** правописание _-тся / -ться_, частицы _не / ни_, дефисы (_кое-как_, _ярко-красный_).
9. **Технические термины и IT-жаргон:** латиница, названия технологий, неологизмы («LexiSync», «Cloudflare», «SmartTube», «промпт», «JSON»).
10. **Сложное форматирование и спецсимволы:** переносы строк `\n`, числа с пробелами (`12 500`), email, URL, эмодзи (`🎉✨`).

Тестирование проводилось в среде Node.js v26 под Windows 11 через прямые HTTP-запросы к боевому API Яндекс.Спеллера, а также через локальный инстанс `BloomRussianDictionary` (2,58 МБ, 1,4M словоформ) и правила `applyLocalTextRules` из LexiSync.

## 6. Детальный анализ результатов по категориям

### 6.1 Простые орфографические ошибки (кейсы 1–5)

- **Яндекс.Спеллер:** Находит 100% орфографических ошибок («Карова», «кампьютер», «тексст», «ашибки», «пагода», «исправте»). Предлагает качественные подсказки в 1-й позиции списка.
- **Local Proofreader:** Исправляет слова, входящие в детерминированные правила (`CERTAIN_CORRECTIONS` и `COMMON_TYPOS`). Для неизвестных слов (например, «велосепеде») отмечает ошибку, но автозамену не производит, чтобы исключить ложные исправления.
- **Вывод:** В чистой словарной орфографии Спеллер превосходит компактный фильтр Блума по полноте словаря и качеству ранжирования подсказок.

### 6.2 Контекстные опечатки и паронимы (кейсы 6–9)

- **Яндекс.Спеллер:**
    - Обнаружил n-граммную аномалию в «скучать музыку» и предложил «скачать» (отличный результат!).
    - **Пропустил** паронимы «компания/кампания» и «одел/надел пальто», а также управление «оплатить за проезд».
- **Local Proofreader:** Благодаря явному правилу `одеть (пальто|куртку...)` $\to$ `надеть` мгновенно исправил кейс 8, но бессилен в остальных контекстных случаях.
- **Вывод:** Спеллер помогает в расхожих n-граммах («скучать музыку»), но не является полноценным грамматическим анализатором паронимов.

### 6.3 Повторение слов (кейсы 10–12) — неожиданный эмпирический факт!

- Несмотря на то, что флаг `FIND_REPEAT_WORDS` (`options=8`) прямо описан в официальной документации Яндекс.Спеллера, в боевом API запросы с `options=8` **не вернули ни одной ошибки повтора** (ни на «сегодня сегодня», ни на «написал написал», ни на «в в»).
- **Вывод:** Опция 8 в текущем публичном API либо отключена на стороне бэкенда Яндекса, либо требует недокументированных условий. Полагаться на Спеллер для удаления дублей слов нельзя.

### 6.4 Регистр букв (кейсы 13–14)

- Спеллер полностью проигнорировал ошибки «мОСКВЕ» (код 3 `ERROR_CAPITALIZATION` не был сгенерирован) и строчное «санкт-петербург».
- **Вывод:** Проверка регистра в публичном API работает крайне толерантно и не исправляет случайный CapsLock внутри слова.

### 6.5 Грамматическое согласование (кейсы 15–18)

- Ошибки рода и числа («Мы вчера ходил», «Она купил», «два красивых книга») Спеллер **полностью игнорирует**, что прямо зафиксировано в документации сервиса («грамматические ошибки не исправляются»).
- Единственное исключение — кейс 18 («много интересный фильмов» $\to$ «много интересных фильмов»), где сработала n-граммная модель коллокаций.
- **Вывод:** Задачу согласования членов предложения Спеллер решить не может; здесь безальтернативно требуется LLM.

### 6.6 Пунктуация (кейсы 19–25)

- **Яндекс.Спеллер показал 0% детекции пунктуации.** Ни запятые в сложноподчинённых предложениях («Я думаю что»), ни вводные слова («Это конечно странно»), ни знаки препинания в конце фраз («Привет как дела») Спеллер не видит в принципе.
- **Вывод:** Спеллер — это узкоспециализированный _орфографический_ корректор, а не пунктуатор.

### 6.7 Ложные срабатывания (кейсы 26–30)

- И Яндекс.Спеллер, и Local Proofreader показали **0 ложных срабатываний** на заведомо правильных текстах. Никаких ложных замен URL (`https://example.com`), дат или чисел не произошло.

### 6.8 Орфография повышенной сложности: -тся / -ться, не / ни, дефисы (кейсы 31–39)

- **-тся / -ться:** Яндекс.Спеллер показал **100% точность** на всех трёх тестах («встретится» $\to$ «встретиться», «учится» $\to$ «учиться», «получиться» $\to$ «получится»). Так как обе формы существуют в словаре, обычный словарь Блума их не различает, а статистическая n-граммная модель Спеллера справилась безупречно.
- **не / ни:** Спеллер распознал раздельное ошибочное написание «не чего» $\to$ «нечего».
- **Дефисы:** Спеллер пропустил «кое как» и «ярко красное», но исправил слитное «Повидимому» $\to$ «По-видимому».

### 6.9 Технические термины и IT-жаргон (кейсы 40–42)

- Яндекс.Спеллер **не дал ни одного ложного срабатывания** на слова: `LexiSync`, `Cloudflare`, `TypeScript`, `GitHub`, `Keenetic`, `SmartTube`, `VPN`, `ChatGPT`, `JSON`, `промпт`.
- Локальный словарь LexiSync выдал флаг `unknown_word` для слов «роутере» и «валидный» (их нет в словаре 2009 года `dictionary-ru`), что потребовало бы их добавления в белый список.

### 6.10 Форматирование, HTML, длина текста (кейсы 43–45 и стресс-тесты)

- **Длина текста:** В документации заявлен лимит 10 000 символов. Тест текста длиной **12 600 символов** прошел успешно (HTTP 200, обработано 900 ошибок, позиция последней — 12 588). Сервис не оборвал соединение и не выдал 413.
- **HTML:** При передаче `format=html` Спеллер корректно игнорирует теги (`<p>`, `<b>`, `<span>`) и возвращает ошибки только внутри текстовых узлов с точными смещениями.
- **Эмодзи:** Наличие символов Unicode (🎉✨) не сдвигает позиции последующих слов в UTF-16.

## 9. Конфиденциальность (Privacy) и безопасность данных

Это один из самых критичных аспектов для LexiSync:

1. **Local Proofreader LexiSync:**
    - Данные пользователя **никогда не покидают браузер**.
    - 0 сетевых запросов, 0 рисков перехвата.
    - Полное соответствие политике конфиденциальности Chrome Web Store и Mozilla Add-ons («No Remote Code / No Data Collection»).

2. **Яндекс.Спеллер:**
    - Текст **целиком передается на серверы Яндекса** открытым или TLS-пакетом.
    - Если пользователь проверяет конфиденциальный документ, письмо с паролями, номерами карт или персональными данными (PII), этот текст логируется на серверах третьей стороны в юрисдикции РФ.
    - Для пользователей за пределами РФ или пользователей корпоративных политик отправка текста в Яндекс без явного согласия является нарушением доверия.

3. **Cloudflare / Mistral в LexiSync:**
    - Пользователь вводит **свой собственный API-ключ** (BYOK — Bring Your Own Key) и лично выбирает доверенного провайдера.
    - LexiSync маскирует PII (email, телефоны, ключи) через модуль `pii-masker` перед отправкой в LLM.

## 11. Варианты возможной интеграции

### Вариант A: Полная замена Local Proofreader на Яндекс.Спеллер

- **Суть:** Вырезать Bloom-словарь и проверять всё через Спеллер.
- **Оценка:** **КАТЕГОРИЧЕСКИ НЕ РЕКОМЕНДУЕТСЯ.**
    - Убьёт автономность LexiSync (расширение перестанет работать без интернета).
    - Нарушит главное обещание приватности («Локальная проверка не отправляет данные в сеть»).
    - Лимит 10 000 запросов на IP приведет к отказам в корпоративных или VPN-сетях.

### Вариант B: Трёхслойный каскад (L1 Local $\to$ L2 Speller $\to$ L3 AI)

- **Суть:** Сначала 0 мс локальная проверка; если пользователь нажал «Проверить», быстрый вызов Спеллера (79 мс) для точной орфографии и _-тся/-ться_, а затем (при необходимости пунктуации или стиля) вызов LLM.
- **Оценка:** **ВОЗМОЖНО, НО ИМЕЕТ СЕРЬЁЗНЫЕ ОГРАНИЧЕНИЯ.**
    - Спеллер все равно не решает проблему пунктуации, поэтому для большинства пользователей вызов LLM всё равно потребуется.
    - Потребуется встроить в интерфейс заметную надпись «Проверка правописания: Яндекс.Спеллер» со ссылкой, что ухудшит UI.

### Вариант C: Опциональный провайдер в настройках («Включить Яндекс.Спеллер»)

- **Суть:** По умолчанию выключен. Пользователь может включить чекбокс «Использовать Яндекс.Спеллер для быстрой орфографии без ключей AI» с явным предупреждением о передаче текста в Яндекс.
- **Оценка:** **НАИБОЛЕЕ БЕЗОПАСНЫЙ И ТЕХНИЧЕСКИ ОПРАВДАННЫЙ ВАРИАНТ.**
    - Не нарушает приватность пользователей по умолчанию.
    - Даёт возможность быстрой проверки орфографии тем, у кого нет API-ключей Cloudflare или Mistral.
    - Выполняет юридические требования п. 3.8 только на экранах пользователей, включивших эту функцию.

### Вариант D: Отказ от интеграции

- **Суть:** Оставить текущую архитектуру (Local Bloom + Cloudflare/Mistral AI). Вместо внешнего API расширить локальные правила `local-text-rules.ts` эвристиками для _-тся/-ться_ и дополнить Bloom-словарь современными IT-словами («роутер», «валидный»).
- **Оценка:** **СИЛЬНАЯ АЛЬТЕРНАТИВА.**
    - Сохраняет нулевую внешнюю зависимость.
    - Никаких юридических обязательств перед Яндексом.
    - 100% приватность без передачи данных третьим лицам.

## 12. Плюсы и минусы Яндекс.Спеллера для LexiSync

### Достоинства (+):

1. **Высокая точность орфографии:** великолепно знает морфологию русского языка (база ОРФО) и исправляет сложные опечатки.
2. **Безупречное распознавание -тся / -ться:** решает главную проблему простых локальных словарей благодаря n-граммному анализу контекста.
3. **Высокая скорость:** медиана 79 мс (в 7 раз быстрее нейросетей).
4. **Не требует API-ключей:** готов к работе «из коробки», не требует регистрации и настройки кредитных карт.
5. **Низкий уровень False Positives:** не ломает технические термины, URL, числа, пути и эмодзи.
6. **Поддержка HTML:** умеет проверять разметку, игнорируя теги.

### Недостатки (-):

1. **Полное отсутствие проверки пунктуации:** не ставит запятые, тире, точки, вопросительные знаки.
2. **Слабая грамматика:** не видит несогласованность рода, числа и падежа («Мы вчера ходил»).
3. **Неработающий флаг повторов:** `options=8` не детектирует повторы слов в боевом API.
4. **Угроза приватности:** весь текст передаётся на сторонние серверы.
5. **Юридическое требование атрибуции (п. 3.8 ToS):** обязательный видимый текст «Проверка правописания: Яндекс.Спеллер» с активной ссылкой шрифтом основного размера.
6. **Суточный лимит 10 000 запросов / 10M символов на IP:** риск исчерпания лимита при общем NAT/VPN.
7. **Работает только онлайн:** при отсутствии интернета расширение вернёт ошибку.

## 13. Ответы на 5 ключевых вопросов задания

### 1. Может ли Спеллер заменить Local Proofreader?

**НЕТ, НЕ МОЖЕТ.**
Local Proofreader ценен именно тем, что он работает **локально, мгновенно (0 мс), оффлайн и со 100% гарантией конфиденциальности**. Замена его на сетевой вызов к Яндексу лишит LexiSync его главного конкурентного преимущества в магазинах расширений — приватности и оффлайн-работы.

### 2. Может ли Спеллер заменить AI-проверку?

**НЕТ, НЕ МОЖЕТ.**
Яндекс.Спеллер не выполняет исправление пунктуации, не согласует сложные синтаксические конструкции, не умеет менять стиль текста, объяснять ошибки или делать рерайт. Пользователям LexiSync требуется комплексная коррекция (орфография + пунктуация + типографика), которую Спеллер в одиночку обеспечить не способен.

### 3. Стоит ли делать гибрид (Спеллер + AI)?

**ТОЛЬКО КАК ОПЦИОНАЛЬНЫЙ РЕЖИМ (Вариант C).**
Для пользователей, у которых **нет API-ключей** Mistral или Cloudflare, Спеллер может служить промежуточным «бесплатным онлайн-исправителем орфографии», существенно превосходящим автономный словарь Блума в части _-тся/-ться_. Однако для пользователей с настроенным AI вызов Спеллера избыточен: модель `GLM-4.7-Flash` за ~585 мс качественно исправляет и орфографию, и пунктуацию за один проход.

### 4. Каковы риски приватности?

**ВЫСОКИЕ.**
Любой введенный текст отправляется в открытом или зашифрованном виде на серверы Яндекса. В тексте могут присутствовать пароли, персональные данные клиентов, токены авторизации или конфиденциальная переписка. Без предварительного согласия пользователя (Opt-In) интеграция такого сервиса недопустима.

### 5. Каковы юридические риски?

**СУЩЕСТВЕННЫЕ.**
Пункт 3.8 соглашения обязывает разработчика размещать фразу _«Проверка правописания: Яндекс.Спеллер»_ со ссылкой размером не менее основного шрифта на экране результатов. Скрытое использование API без указания ссылки прямо нарушает условия сервиса и может повлечь блокировку по User-Agent/IP.

## 14. Рекомендации по дальнейшим шагам для LexiSync

1. **Не включать Яндекс.Спеллер в обязательный конвейер по умолчанию.**
   Сохранить базовую философию:
    - Слой 1: **Local Proofreader** (автономный, приватный, 0 мс).
    - Слой 2: **Cloudflare Workers AI / Mistral AI** (полноценный интеллект по ключу пользователя).

2. **Рассмотреть добавление Яндекс.Спеллера в качестве опционального бесплатного провайдера орфографии:**
    - Переключатель в настройках: `[ ] Использовать Яндекс.Спеллер для быстрой онлайн-орфографии (без API-ключа)`.
    - Рядом явная плашка соответствия п. 3.8: _«Используется технология Яндекс.Спеллер»_ со ссылкой.
    - Обязательное предупреждение о передаче текста третьей стороне.

3. **Улучшить собственный Local Proofreader без внешних зависимостей:**
    - Добавить в `src/local-rule-engine.ts` синтаксические regex-эвристики для глаголов на _-тся / -ться_ (например, после модальных слов «надо», «хочет», «может», «пытается» + глагол с «-тся» $\to$ «-ться»).
    - Дополнить `TECHNICAL_WORDS` и локальный словарь терминами: «роутер», «валидный», «эмодзи», «смайлик», исключив ложные срабатывания.
