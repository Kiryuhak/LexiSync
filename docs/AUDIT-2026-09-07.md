# Аудит LexiSync: подготовка 5.6.0

Исходная версия — 5.5.8. Сохранён пользовательский коммит перехода на GigaChat; история Git не переписывалась.

## Архитектура и исправления

- WXT собирает Manifest V3 отдельно для Chrome (service worker) и Firefox (background scripts). UI и content передают команды фоновому менеджеру Mistral/GigaChat.
- OAuth-кэш перенесён из общего storage.local в приватную IndexedDB. Запись содержит отпечаток Authorization Key, но не его копию. Старый общедоступный кэш удаляется при запуске миграции.
- Single-flight объединяет параллельные запросы одного ключа. Отмена ожидания отдельной команды не отменяет общий OAuth. Запись запоздалого токена после смены ключа запрещена.
- При 401 отклонённый токен удаляется только если он всё ещё текущий; допускается одно обновление и один повтор. Несохранённый ключ проверяется без замены рабочего токена.
- Проверки настроек перенесены в background и доступны только страницам расширения. Сайтам не возвращаются ключи или токены.
- Резерв разрешён только для 429, сетевой ошибки, тайм-аута и 5xx. Ошибки ключа, HTTP 400/404/422, некорректный ответ и отмена не вызывают переход. После резервной попытки возврата к первому провайдеру нет.
- Исправлен ложный успешный статус GigaChat по наличию токена: проверяется endpoint моделей. Незавершённый поток без DONE не считается успехом. Читатели освобождаются в finally.
- Адреса и модели Mistral берутся из AI_CONFIG. Из настроек удалена оставшаяся подпись Qwen. Причина временного исключения провайдера из маршрута сохраняется для корректного уведомления.
- Консоль использует ту же очистку, что экспорт журнала; маскируются Basic, Bearer, access_token и известные форматы ключей. Тело ошибки OAuth в журнал не попадает.

## Безопасность и совместимость

Обязательные API-hosts: api.mistral.ai, ngw.devices.sberbank.ru, api.giga.chat. Разрешения storage, activeTab, scripting и contextMenus сохранены; новые разрешения не добавлены. Доступ ко всем веб-страницам остаётся запрашиваемым отдельно, а не обязательным ради AI.

Результаты AI вставляются через безопасные DOM-операции, интерфейс страницы изолирован Shadow DOM. В релизных манифестах проверяются отсутствие отладочного доступа и опасной CSP. Сохраняются проверки приватных окон, исключённых сайтов, отмены операций и бюджетного резервирования.

В рабочем коде прежний провайдер остался только в очистке старого ключа; исторические записи изменений сохранены. Проверка замены текста и геометрии всплывающего окна выполняется также на тестовых textarea, contenteditable и iframe.

## Зависимости

`npm outdated` проверен. Изменён только fast-uri 3.1.5 → 3.1.6: исправления безопасности без major-обновления инструментария. Runtime-зависимостей у расширения нет.

Полный npm audit продолжает отмечать два известных advisory image-size в цепочке addons-linter → web-ext → WXT (четыре затронутых dev-пакета). Они уже ограниченно разрешены существующим audit-tooling; список исключений не расширялся. Автоматический откат WXT/web-ext на несовместимые старые версии не выполнялся. Аудит готового расширения без dev-зависимостей не содержит уязвимостей.

## Проверки и ограничения

Добавлены тесты приватного OAuth-кэша, восстановления после перезапуска модуля, смены ключа, параллельного ожидания, отмены, запоздалого 401, ограничения повторов, неполного потока, здоровья API и запретов fallback. Покрытие расширено на менеджер AI и GigaChat, прежние пороги не снижены.

Полный релизный контроль: форматирование, ESLint, TypeScript 7 и 6, локализация, SVG, audit, unit/coverage, ZIP обоих браузеров, манифесты и web-ext lint, 70 сценариев Chrome и отдельный запуск Firefox. В CI используется тот же `npm run test:all`.

Тесты API используют подменённые ответы и не расходуют платные токены. Они проверяют поведение кода, но не подтверждают состояние личного тарифа, доступность сервера из сети пользователя или доверие сертификатам. OCR требует ключа Mistral; GigaChat используется для текстовых команд. Проверка моделей не гарантирует права на генерацию. Локальные счётчики — оценки, не данные биллинга.

Успешная отправка в магазин и завершение его модерации — разные этапы; окончательные статусы берутся из release workflow и кабинетов магазинов, а не из факта создания тега.
